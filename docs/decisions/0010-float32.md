# 0010: Go's float32 fields are Float32; int32 stays Int

Status: Accepted (owner, 2026-11-07, through the lead). It matches the
AWS SDK port's decision 0010 for Smithy `float` members.

## Context

azure-sdk-for-go keeps an OpenAPI `number` with `format: float` (and a
TypeSpec `float32`) as Go's `float32`, and `int32` as `int32`. The
generator mapped every `number` to Xo's `Float` (64 bits) and every
`integer` to `Int`. A float32 value read from the wire is then held at
float64 precision where Go rounds it to float32, and written back as
text Go would not write.

Size, from Go's modules: 619 float32 fields in 63 modules, and 14
float32 query parameters (armbilling, armbillingbenefits,
armreservations). No Go ARM module reads a float32 response header.

## Decision

- A `number` with `format: float`, and a TypeSpec `float32`, is
  `Float32`. Every other `number` stays `Float`.
- `int32` stays `Int`: Xo's `Int` holds every int32, and Go's range
  check on an int32 is not a wire behavior.
- A float32 path, query or header value is written as Go's
  `strconv.FormatFloat(float64(f), 'f', -1, 32)`: azcore's
  `float32_text`, the shortest decimal that reads back as the same
  float32 (checked against Go for 2000 values in
  `azcore/float32_test.xo`). Xo's own Display of a Float32 prints the
  float64 shortest form, so azcore finds the float32 digits itself (the
  AWS port's `shortest32`).
- A JSON body reads a Float32 as Go does (one rounding to float32, an
  error past its range) through `derive Json`. Writing it as Go's
  `encoding/json` does (the float32 shortest text) needs std/json to do
  so; that std change is assigned to the std lane. Until it lands,
  `azcore/float32_json_test.xo` pins the difference, and azcore's copy
  of the formatter goes once std has it.

## Consequences

- The field type of the 619 fields is `Float32` from the first
  generation of each module; for the modules already ported (armcompute,
  armcontainerservice, armcosmos, armnetwork, armstorage, armappservice
  and the data plane azbatch, azopenai, azsystemevents) the change is
  their field types only.
- A float32 written in a JSON body differs from Go's text (`1.1` written
  as `1.100000023841858`) until the std change; the value read back is
  the same float32.

## Alternatives

- **Keep `Float`**: no API change, but
  values and text differ from Go's.
- **An `azcore.Float32` wrapper with its own JSON**: Go's text today
  without a std change, but a field type that is not Xo's own Float32.
