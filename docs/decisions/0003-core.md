# 0003: The hand written core

Status: Accepted (owner, 2026-11-05; proposed by Xo Azure 1, 2026-11-05)

## Context

azcore and azidentity hold everything a generated client calls: the HTTP
pipeline and its policies, errors, clouds, long-running operation pollers,
pagers, the ARM extras, and the Entra ID credentials (azidentity uses MSAL
Go underneath). Each piece is ported from its Go source, with MIT
attribution (decision 0007). Every Xo std piece it needs exists (http,
json, xml, crypto with RSA-PSS and HMAC, x509, jwt, uuid, time, url),
except those in decision 0006.

## Decision

### Pipeline (`runtime`, `policy`)

- A pipeline is a list of policies, each `fn(req, next) -> Response !
  Err`, in azcore's order: include response, api-version (when the client
  sets one), telemetry, the per-call policies (the client's, then the
  caller's), retry, the per-retry policies (the client's, then the
  caller's), request headers, logging, body download, transport.
- **Retry:** azcore's defaults: 3 retries, 800 ms delay doubling
  (`(2^try - 1) * 800 ms`, jitter 0.8 to 1.3), at most 60 s; retried
  statuses 408, 429, 500, 502, 503, 504 and connection errors; the
  server's delay from `Retry-After-Ms`, `x-ms-retry-after-ms`, then
  `Retry-After` (seconds or an HTTP date), and no retry when it exceeds
  the maximum. A per-try timeout. Sleeps on `Clock`, jitter from `Rand`,
  so tests run on fake time.
- **Telemetry:** `User-Agent: [<application id> ]xo-lang-azure-<module>/<version> (xo/<version>; <os>)`.
  It follows azcore's shape so Azure's telemetry can group it, under a
  name that cannot be taken for Microsoft's (`azsdk-go-` is Microsoft's).
  The application id is truncated to 24 characters with spaces made `/`,
  as in azcore.
- **Request ID:** `x-ms-client-request-id` is a new UUID per call when
  absent. azcore has the policy but not in its default pipeline; the
  other Azure SDKs send it, and it is what Azure support asks for.
- **Logging** with allowed headers and query parameters only (others
  printed as `REDACTED`), the body only when asked; `Authorization` and
  SAS signatures are always redacted.
- **Clouds** (`cloud`): AzurePublic, AzureChina, AzureGovernment with
  their authority hosts and ARM endpoints and audiences, as azcore's
  table.

### Errors (`azcore.ResponseError`)

Status, error code (the `x-ms-error-code` header, else the JSON body's
`error.code`, `odata.error.code` or `code`, else the XML `<Code>`), the
raw response, and a message with the method, URL, code and body, as
azcore's.

### Pagers and pollers (`runtime`)

- `Pager[T]` with `more()` and `next_page() -> T ! Err`, following
  `nextLink` (made absolute and its query re-encoded as azcore does).
- `Poller[T]` from a long-running operation's first response, choosing
  azcore's kind in its order: `Azure-AsyncOperation`, `Operation-Location`,
  `Location`, then the body's `provisioningState` for a PUT or PATCH;
  terminal states Succeeded/Completed and Failed/Canceled/Cancelled; the
  final GET by method and `final-state-via`. `poll()`, `done()`,
  `result()`, and `poll_until_done(frequency = 30s)` that honors
  `Retry-After`. `resume_token()` writes azcore's JSON (`{"type": ...,
  "token": {...}}` with the same field names), so a token can move
  between a Go and an Xo program.

### ARM (`arm`)

- The bearer token policy with the cloud's ARM audience plus
  `/.default`, refreshing at the token's refresh time or 5 minutes before
  it expires; auxiliary tenants (`x-ms-authorization-auxiliary`).
- Resource provider registration as azcore's: on 409 with
  `MissingSubscriptionRegistration` (and its three other spellings),
  register the provider, poll it every 15 s for up to 5 minutes, retry
  the call; `disable_rp_registration` turns it off.

### Credentials (`azidentity`)

- `TokenCredential` is an interface: `get_token(opts) -> AccessToken !
  AuthErr uses (net.dial, clock, rand)`, `opts` holding scopes, tenant
  and claims. Implemented by hand (no MSAL): the OAuth 2.0 client
  credentials grant at `<authority>/<tenant>/oauth2/v2.0/token`.
- Credentials, in DefaultAzureCredential's order:
  1. **Environment:** `AZURE_TENANT_ID`, `AZURE_CLIENT_ID` with
     `AZURE_CLIENT_SECRET` or `AZURE_CLIENT_CERTIFICATE_PATH` (and
     password). Username and password is left out (deprecated, no MFA).
  2. **Workload identity:** `AZURE_FEDERATED_TOKEN_FILE` as a client
     assertion. The file is read when the credential is built and reread
     by a background watch, as the AWS SDK's token files.
  3. **Managed identity:** App Service (`IDENTITY_ENDPOINT`,
     `IDENTITY_HEADER`), Service Fabric, Azure ML and Cloud Shell
     (`MSI_ENDPOINT`), then IMDS (`169.254.169.254`, `Metadata: true`,
     a 1 s probe inside the default chain), each as MSAL sends it.
     Azure Arc needs to read a key file the server names in its 401, a
     file read inside `get_token`; it comes later, with the same
     background task pattern as the AWS SDK's credential_process.
  The Azure CLI, Azure Developer CLI and PowerShell credentials are out
  (the brief: not without the owner's word). `AZURE_TOKEN_CREDENTIALS`
  (`prod`, or one credential's name) selects as in azidentity.
- **ClientSecretCredential** and **ClientCertificateCredential**: the
  certificate signs a client assertion JWT (aud the token endpoint, iss
  and sub the client id, a UUID jti, 10 minutes) with PS256 and an
  `x5t#S256` header, as MSAL does. PEM certificates first; PKCS#12
  (`.pfx`) waits on std (decision 0006).
- A token cache per credential: one task refreshes while others wait,
  at `refresh_in` when the server sends it, else 5 minutes before
  expiry.
- Secrets are `Secret[Str]`, never logged.

### Data plane signing

- **Storage Shared Key** (Blob, Queue, File: the 12 standard headers,
  the canonicalized `x-ms-` headers and resource; Table SharedKey and
  SharedKeyLite), and **SAS** (account, service and user delegation),
  as azblob's `shared_key_credential.go` and `sas/` build them.
- **Key Vault challenge auth:** the first request without a body or
  token, then the scope and tenant from the 401's `WWW-Authenticate`,
  with the host check, as Key Vault's challenge policy.
- **Cosmos DB master key:** `type=master&ver=1.0&sig=...` over the
  verb, resource type, resource link and date, as azcosmos.

### Owner notes (2026-11-05)

- Azure Arc managed identity comes later.
- The Azure CLI credential is not in now; it may come later as an
  opt-in, through its own decision record. The Azure Developer CLI and
  PowerShell credentials stay out.

## Consequences

- No MSAL port: only the client credentials grant and managed identity
  are needed for service credentials; interactive and device code flows
  are out of scope until asked.
- Pollers' resume tokens interoperate with Go's.

## Alternatives

- Port MSAL Go whole: interactive flows, the shared token cache, and
  much code the server-side credentials do not need.
- A single combined token cache file on disk (as MSAL's persistent
  cache): would need file effects in every credential.

## Amendment 1

Status: Proposed (Xo Azure 1, 2026-11-06, at the Xo Lead's request; the
owner accepts it)

- **The token cache is public**: `runtime.TokenCache` and
  `runtime.token_cache(credential, scopes, clock, enable_cae = true)`
  with `get()`, `get_for_claims(claims)` and `reset()`, shared by every
  copy, one refresh at a time (the cache this decision already
  describes, now usable on its own). `BearerTokenPolicy` keeps one.
  A policy that writes the token in its own header shape uses one
  instead of copying the cache: Cosmos DB's `type=aad&ver=1.0&sig=`
  (azcosmos, without CAE, as Go's cosmosBearerTokenPolicy).
- Go keeps the equivalent (`temporal.Resource`) internal and has
  azcosmos build its own policy on it; Xo's packages are one module
  set, so exposing it costs one public type and removes a second
  cache.
- **Policies can be told about the operation and can end retries**
  (azure, with azcosmos's retry and failover): `policy.Request.values`
  (`Map[Str, Str]`, never sent; azcore's SetOperationValue) and two
  `policy.SendErr` variants, `Final(http.ClientErr)` and
  `FinalResponse(http.Response)`, that azcore's retry policy does not
  retry (azcore's NonRetriableError). A client maps `FinalResponse` to
  its response error.
- Additive: no existing signature changes (a `match` on `SendErr`
  outside this repo gains two arms).
